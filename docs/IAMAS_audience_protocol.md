# Fragmentations of Unity — 観客検出データ受け渡し仕様（IAMAS展示用）

作品側（FU）が観客の位置情報を受け取るためのプロトコル仕様です。
検出システム側はこの仕様で座標を publish してください。

## トランスポート

| 項目 | 値 |
|---|---|
| プロトコル | **MQTT**（OSCではありません） |
| ブローカー | NanoMQ。FU側のマシンで稼働（会場LAN内、例: `192.168.1.2`、IPは現地で確定） |
| ポート | 1883（認証なし・平文） |
| QoS | 0 |
| トピック | `ca` （coordinate of audience） |

※ 補助トピックとして `ss`（sound source、音源位置1点）も同じ形式で購読していますが、今回は `ca` のみで OK です。

## ペイロード（バイナリ・可変長）

1人あたり **big-endian の signed int16 ×2 = 4 byte** `(x_cm, y_cm)` を人数分連結します。

```
0人 : （空ペイロード、0 byte）
1人 : >hh        … 4 byte
2人 : >hhhh      … 8 byte
N人 : 4 × N byte
```

- 単位は **cm**（FU側で m に変換します）
- ペイロード長が 4 の倍数でない場合は破棄されます
- **人物IDはありません。** 並び順は任意ですが、フレーム間で同一人物が同じインデックスに来るよう（トラッキング順を維持して）送ってもらえると表現が滑らかになります

## 送信頻度・タイムアウト

- **10 Hz 程度で常時送信**してください（人数・座標に変化がなくても送る）
- **誰もいないときも空ペイロードを送り続けて**ください
- FU側は **1.0 秒**受信が途絶えると「観客なし」として扱います

## 座標系（配置キープラン U-01 基準）

- 床面の2次元座標 `(x, y)`、単位 cm（符号付き整数）
- **原点 = 作品（ユニット5本の群）の中心直下の床**、**+x = 東（ユニットのレール方向）**、**+y = 北（上壁側）**
- 例: 作品中心から東へ1.2m・南へ0.8mの観客 = `(120, -80)`
- 検出範囲の目安: 観客ゾーン（幅約10m×奥行き約11.5m）全体をカバーできると理想。最低限、作品中心から半径約3mあれば演出に使えます（int16 なので ±327 m まで表現可能、範囲外の値も受信自体は問題なし）
- 設営時に原点と軸を床にマーキングして現地すり合わせ

## 送信サンプル（Python / paho-mqtt）

```python
import struct, time
import paho.mqtt.client as mqtt

client = mqtt.Client()
client.connect("192.168.1.2", 1883, 60)   # FU側マシンのIP
client.loop_start()

while True:
    people = [(120, -80), (-45, 230)]     # [(x_cm, y_cm), ...] 0人なら []
    payload = b"".join(struct.pack(">hh", x, y) for x, y in people)
    client.publish("ca", payload, qos=0)
    time.sleep(0.1)                        # 10 Hz
```

コマンドラインでの単発テスト（1人 = (1.2 m, -0.8 m)）:

```bash
mosquitto_pub -h 192.168.1.2 -t ca -m "$(printf '\x00\x78\xff\xb0')"
```

## 動作確認

FU側のシミュレータ（`choreography/main.py`）を Sensor ON にすると、受信した座標が観客として3D/2Dビューに表示されます。会場設営前にローカルブローカー（`localhost:1883`）で疎通テスト可能です。
